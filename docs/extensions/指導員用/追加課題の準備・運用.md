# 指導員用：追加開発の準備・運用

**この資料は訓練生への配布対象外です。** `docs/extensions/`の設計書・Issue・テスト仕様のみを配布します。

## 現行開発に影響させない導入手順

1. 現行の`master`から準備用ブランチ`docs/extension-planning`を作る。ドキュメントのみを準備する。
2. 現行版の実装・結合試験を完了させ、`master`へ`v1.0`タグを付ける。
3. 準備用ブランチに最新`master`を反映し、完成版コード・テストとの整合性を確認する。
4. `docs/extensions/`だけをPRで`master`へマージする（本資料は含めない）。
5. 実施する課題だけをGitHub Issueとして起票し、最新の`master`から作業ブランチを作る。

## Project／Milestone

- Projectの追加課題専用ビューを作り、未着手のものはBacklogとして保持する。`Estimate (h)`はNumber型。
- 機能単位を独立して完成できるよう、基本は1作業記号を1つのMilestoneに対応させる。必要に応じて小さなMilestoneをまとめてもよい。
- 達成条件は、Issueを閉じたことではなく、実際に画面・API・DBが必要な範囲で動作し、該当テストに合格したこと。
- 次の課題に着手するだけの時間がなければ、動作する完成段階で終了する。

## 配布前の確認

- 現行版の完成コードとAPI・テスト構成が一致しているか。
- OracleのDDLを訓練生自身に考えさせるため、テーブルの列・主キー・外部キーは示すがSQLの完成文は配らない。
- `SENSOR_LOCATION`（場所）、`IOT_DEVICE`（デバイス）、`SENSOR_ASSIGNMENT`（割当）の名称で統一されているか。
- Chart.jsをローカル利用するためのファイルとライセンスの準備。
- GitHub Issueに起票する内容は、課題の選択に合わせて調整する。
