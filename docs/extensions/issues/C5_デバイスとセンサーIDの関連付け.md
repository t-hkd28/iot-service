# デバイスとセンサーの関連付け（C5）

> **作業名の確認：** [タスク早見表](../タスク早見表.md)（D0・B1・A1などの記号と担当機能の対応）
- **種別：** enhancement / area:device
- **見積工数：** 11人時（実装・テスト・修正・PR）
- **前提Task：** 設置場所マスタ・デバイス登録／一覧（C1）、測定日時範囲検索（B2）
- **対応Milestone：** [GitHub運用](../github/準備ブランチ・Milestone・PR運用.md)を参照
- **詳細設計：** [設計書](../design/C_デバイス管理.md)
- **テストケース：** C5-01～04（[テスト一覧](../tests/README.md)）

## 目的

センサーIDとデバイスIDを分けたまま関連付け、測定データにアクセスする。

## 主な作業

DEVICE_SENSOR表、割当/解除/一覧API、関連センサーUI、デバイスIDから関連センサーIDをサーバー内で解決し、専用のデバイス別測定データAPIで取得する。

## 終了条件（Definition of Done）

- [ ] 1デバイスに複数IDを割当可能、1 IDの二重割当は拒否、デバイス詳細からデータを閲覧可能。
- [ ] 対応するテストケースを実施し、結果をPRに記録した。
- [ ] 既存の`GET /api/sensors?limit=1`とOracle利用経路に問題がない。
- [ ] 新機能に必要なAPI・DB・画面まで実際に確認した（該当しない層は除く）。
- [ ] レビューを受け、`master`へマージ可能な状態になった。

## 実装上の注意

- 追加課題用のブランチは`v1.0`タグ付けと設計資料のマージの**後**に最新`master`から作成。
- 新しい未完成機能を前提にしない。現段階だけで動作できること。
- 最小限の入力検証と単純なエラー処理に留める。必要に応じて先行Taskの設計とコードを確認する。
