# 導入手順と現時点の未確定事項

## 資料の導入

このZIPの`docs/extensions/`を、`docs/extension-planning`ブランチのリポジトリ直下へ配置する。`master`へはまだマージしない。現行`v1.0`タグ作成後に、コード・設計の差異を確認してからドキュメントPRをマージする。

## 既存コードに対する重要な注意

- 現行の`SensorData`とSENSOR_DATAの列構成は完成版ZIPで確認した。**追加機能で既存データ形式を変更しない**。
- DBテーブル名・パッケージ名・Javaメソッド名は追加機能の**設計案**であり、現行ソースには存在しない。
- ユーザーの最新方針は「CSVクラスを残し、CSVの切替を廃止」。CSVクラスを削除しない。
- 現行プロジェクトは開発途中であるため、**現在の`master`の最新仕様との差異は未検証**。D0着手前に再確認が必要。
- Chart.jsファイルは含めていない。ライブラリの実体、バージョンとLICENSEの確認・同梱はA1で実施する。
- このZIPにはソースコードや完成テストプログラムを含めていない。設計・テスト仕様・Issue原稿のみ。

## 確定済みの機能範囲

D0、B1～B4、A1～A4、C1～C5。検索は任意条件・AND、IDは別、設置場所はマスタ、グラフは折れ線、Oracleのみ稼働。

## 実装開始前の確認事項

- Oracleのバージョン・DBユーザー・スキーマ作成権限、開発PCからの接続可否。
- デバイスIDとセンサーIDの実際の命名規則（設計例は双方VARCHAR2(50)）。
- A1で固定するChart.jsバージョン・ライセンス、オフライン持込可否。
- `v1.0`タグ時点の実装差異とJUnit起動設定。設計書を最新コードに整合させる。
