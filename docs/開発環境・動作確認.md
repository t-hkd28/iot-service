# 開発環境の設定と動作確認

> **対象**：Eclipseから本プロジェクトを起動するための手順。設計上の仕様は[設計資料](design/README.md)、共同開発手順は[GitHub運用ガイド](GitHubチーム開発_運用ルール・操作手順.md)を参照。

## 1. 必要な環境

| 用途 | 必要なもの | 備考 |
|---|---|---|
| Java開発 | **JDK 21**、Eclipse、Maven | `pom.xml`をMavenプロジェクトとして取り込む |
| CSVでの確認 | 追加サーバー不要 | 標準のCSV保存先は`./sensor-data.csv` |
| JDBCでの確認 | Oracle DB | [テーブル定義](design/外部設計/データ保存形式.md#2-oracle-db)に従って表を作成 |
| MQTTでの確認 | MQTT Broker | 接続先等は[MQTT外部設計](design/外部設計/MQTTメッセージ.md)を参照 |

## 2. Eclipseから起動する

1. `iot-service`のプロジェクトまたは`pom.xml`を右クリック → **実行（Run As）→ Maven ビルド（Maven build...）**。
2. 実行構成の名前を入力する（例：`iot-service CSV`）。**Goals**に`quarkus:dev`を設定する。
3. **環境（Environment）** タブで、必要な環境変数を追加する（下表）。
4. **適用 → 実行**。次回からは保存した実行構成を選択して起動する。
5. 終了時はEclipseのConsoleなどから停止操作を行う。

Mavenを利用できるターミナルの場合は、プロジェクト直下で`mvn quarkus:dev`でも起動できます。※Windowsの環境変数設定はコマンドプロンプトなら`set 名前=値`、PowerShellなら`$env:名前="値"`です。

## 3. 環境変数

値は[`application.properties`](../src/main/resources/application.properties)が参照します。**実際の接続先・認証情報は指導員の指定に従い、Gitに登録しないでください。**

| 変数 | 用途 | 既定値 |
|---|---|---|
| `APP_STORAGE_TYPE` | 保存方式（`CSV` / `JDBC`） | `JDBC` |
| `APP_CSV_PATH` | CSVファイル | `./sensor-data.csv` |
| `APP_MQTT_ENABLED` | MQTT受信の有効化 | `false` |
| `MQTT_BROKER_URL` | MQTT BrokerのURL | `tcp://localhost:1883` |
| `MQTT_CLIENT_ID` | クライアントID | `iot-service` |
| `MQTT_TOPIC` | 購読Topic | `iot/sensor` |
| `MQTT_QOS` | 購読QoS | `1` |
| `DB_JDBC_URL` | Oracle JDBC接続先 | `jdbc:oracle:thin:@//localhost:1521/freepdb1` |
| `DB_USERNAME` / `DB_PASSWORD` | Oracle認証情報 | 空文字列 |

**最初の確認用（Eclipseの環境タブで設定）**：

```text
APP_STORAGE_TYPE=CSV
APP_CSV_PATH=./sensor-data.csv
APP_MQTT_ENABLED=false
```

**MQTT連携を確認するとき**：上記に加え、接続先に応じて`MQTT_BROKER_URL`、`MQTT_CLIENT_ID`、`MQTT_TOPIC`、`MQTT_QOS`を設定し、`APP_MQTT_ENABLED=true`に変更します。**複数PCで同時起動する場合、Client IDを重複させないこと**。必要に応じてTopicも分けます。

**Oracle連携を確認するとき**：`DB_JDBC_URL`、`DB_USERNAME`、`DB_PASSWORD`を設定し、Repository切替機能の完成後に`APP_STORAGE_TYPE=JDBC`を使用します。

> **配布版と完成版の違い**：配布版`RepositoryProducer`は、設定にかかわらずCSV版を返します。ただし`DataSource`を直接注入しているため、CSVを選んでも環境によってはOracle設定の影響を受ける可能性があります。CSV専用環境での起動を保証するには、Issueで扱うProducer実装を見直す必要があります（[Repository内部設計](design/内部設計/Repository.md#2-保存先の生成)）。

## 4. 初期状態と確認できる範囲

| 確認内容 | 配布版の状態 | 確認方法 |
|---|---|---|
| CSVのファイル作成・追記・読み込み | 実装済み | `CsvSensorDataRepository`を直接生成して`save()` / `findAll()`を試す（共通入力検証の担当テストは[Test_01](tests/Test_01.md)。CSV固有の入出力は別途確認する） |
| Repository共通入力検証 | TODO | [Test_01](tests/Test_01.md) |
| REST API / Service / Web JS | TODO | 対応Issueの実装後に確認 |
| MQTT接続・受信・保存 | TODO | `APP_MQTT_ENABLED=true`にする前に実装を完了させる |
| JDBCのINSERT・SELECT / DBテーブル作成SQL | TODO | SQLは[`schema-oracle.sql`](../src/main/resources/db/schema-oracle.sql)に記述する課題 |

**CSVファイル**：`CsvSensorDataRepository`のコンストラクタで存在しないファイルを作成し、空ファイルなら`findAll`は空リストを返します。初期配布版では`APP_STORAGE_TYPE=JDBC`でもCSVが選択されます。

**画面・API確認**：必要なクラスが実装されたら`http://localhost:8080/`、`http://localhost:8080/api/sensors?limit=20`で確認します。[REST API仕様](design/外部設計/REST_API.md)と[画面仕様](design/外部設計/Web画面.md)を参照してください。

## 5. テストと問題発生時

- Javaのテスト：Eclipseで対象のテストを右クリック → **実行 → JUnitテスト**。全体のMavenテストは`mvn test`。
- テストケース・結果の記録方法：[テスト仕様書の使い方](tests/README.md)。
- 実装中の不具合やGit操作の問題：[GitHub運用ガイド](GitHubチーム開発_運用ルール・操作手順.md#8-よくあるトラブルと対応)。
- CSVファイル・ログ・パスワードをCommitに含めない。CSVパスを変更した場合は`.gitignore`の対象外にならないか確認する。
